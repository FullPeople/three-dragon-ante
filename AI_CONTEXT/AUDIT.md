# AI_CONTEXT/AUDIT.md — 三龙牌 独立审计规则

> 实质改动完成后，**开发 AI 不许自宣最终安全**。

## 1. 何时触发

命中任一即实质档、收尾必审：`DOMAIN.md` §3 清单（规则、协议/隐私边界、控制器/持久化、服务端、旧频道兼容、卡图素材、构建入口/manifest、依赖大版本、CI），以及本轮表现层重构的每个阶段收口（至少阶段 2、4、6 各审一次，阶段 7 终审）。
纯文档/注释/拼写 = 轻微档，免审。

## 2. 独立性要求

- **优先换一个模型/工具审**（同模型审自己带同一套盲区）。拿不到才同工具开全新中立只读会话。
- 审计**只读**、**不采信开发者结论**，只按真实文件 / diff / 测试 / 日志 / 截图判断。
- **SOP：至少独立复核 1 条 `MEMORY`/`GOAL` 种子**（抽查它与真实代码是否一致）。
- 本项目特别审查点：① 新 UI 是否在任何投影下渲染了他人手牌正面或牌库顺序；② 提交是否在收到匹配回执前就视觉落地；③ 流程时序规格（`GOAL.md` §4.3）是否成立；④ 打包产物是否有外部请求；⑤ 卡图文件是否被改动；⑥ 是否混入 AI 生成素材或无许可素材。

## 3. 中立开场词（复制给审计 AI）

```
你是独立审计 AI。请只读复核 三龙牌（three-dragon-ante，分支 rebuild/presentation）本次改动，不要采信开发 AI 的结论。
先读 AI_CONTEXT/INDEX.md + GOAL.md + DOMAIN.md 建立上下文，再按真实文件 / git diff / 测试 / 截图判断：
1. 是否符合 GOAL.md 的决策与范围；
2. 是否触碰红线（规则语义、协议/隐私边界、卡图、AI 素材、外部请求）而未经授权；
3. 是否破坏既有不变量（投影不泄私牌、提交≠接受、流程时序规格）；
4. 测试是否真绿、验证是否充分、有无被包装的失败；
5. 是否需要修复。
逐条发现给：文件:行 / 现象 / 影响 / 建议。
报告开头注明你的审计模型（名称+版本）。
裁决：通过 / 有条件通过 / 不通过。
```

## 4. 裁决格式

报告头先注明 **`审计模型：<名称+版本>`**，随后 `通过 / 有条件通过 / 不通过` + 逐条发现 `文件:行 · 现象 · 影响 · 建议`。

## 5. 闭环

有必修 → 修复 → **回同一审计会话**复查 → 通过才算最终交付 → 留痕进 `RUNBOOKS/`（含裁决与修复）。
