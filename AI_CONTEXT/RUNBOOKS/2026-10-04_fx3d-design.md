### 1.2 从 CSS 变换链推导 three.js 相机与矩阵（`stage.ts` 已实现，此处给完整公式便于审计）

记号：`W, H, θ` = `PLANES[orientation]`（landscape 1800×1100 / 28°，portrait 1100×1500 / 22°，`layout.ts:14-17`）；`s` = `--scale` = `fitPlane(R.w, R.h).scale`（`layout.ts:230-237`：`min(R.w/W, R.h/(H·cosθ·1.34|1.24))`）；`d = 1600`，透视原点 `(ox, oy) = (0.5W, 0.3H)`（平面单位，因为 `perspective` 在 `.tda-stage` 的 `scale` 之内）；`cY = 0.46`（portrait 0.47）；`R` = `.tda-table` 盒；`stageLeft = R.w/2 − W·s/2`，`stageTop = R.h·cY − H·s/2`。

**(a) 平面点 → three 世界点（`planeToWorld`，`stage.ts:43-49`）**：以 `(W/2, H/2, 0)` 为 rotateX 原点，`ly = y − H/2`；`ry = ly·cosθ − z·sinθ`；`rz = ly·sinθ + z·cosθ`；世界 `X = x`，`Y = −(H/2 + ry)`，`Z = rz`（three y 向上 = −CSS y；z 朝观者为正；y 越靠本家 Z 越大越近镜头）。

**(b) 世界点 → 宿主像素（`worldToScreen`，`:52-58`）**：眼睛 `E = (ox, −oy, d)`，像平面 `z = 0`；`k = d/(d − Z)`；`sx = ox + (X − ox)·k`，`sy = oy + (−Y − oy)·k`；`px = stageLeft + sx·s`，`py = stageTop + sy·s`（加 `R.left/top` 即 clientX/Y）。

**(c) 空中相机（`airCamera`，`:67-73`；`FxStage.ts:89-93`）**：`PerspectiveCamera` 位于 `E`、旋转 0；宿主矩形换算成像平面上的平面单位 `hl = −stageLeft/s`、`hr = (R.w − stageLeft)/s`、`ht = −stageTop/s`、`hb = (R.h − stageTop)/s`；`n = 60`，`κ = n/d`；`projectionMatrix.makePerspective((hl−ox)κ, (hr−ox)κ, (oy−ht)κ, (oy−hb)κ, n, 6000)`；`updateProjectionMatrix` 覆写为重算这组值（`FxStage.ts:104`，防 three 内部 `setViewOffset` 改回对称视锥）。`renderer.setSize(R.w, R.h, false)` → 像素一一对应。

**(d) 平面组**：`group.position = (W/2, −H/2, 0)`，`group.rotation.x = −θ`（`FxStage.ts:94`）；**统一局部坐标** `local(x, y, z) = (x − W/2, H/2 − y, z)`。验算：平面点 `y = H/2 + t` → 组内 `(0, −t, 0)` → 绕 x 转 −θ → `(0, −t·cosθ, t·sinθ)`，与 CSS 的 `(Y 下移 t·cosθ, Z 近 t·sinθ)` 一致。

**(e) 地面相机（P0 修正后）**：`OrthographicCamera(−W/2, W/2, H/2, −H/2, −2000, 2000)`，`position.z = 1000`，物体也用 `local(x, y, 0)`（z 仅作 renderOrder 辅助）。无反射 → 投影矩阵行列式与标准 y-up 相机同号 → `FrontSide` 正常。

**(f) 反向：宿主像素 → 平面点 z=0（`screenToPlane`，`:76-91`）**：像平面点 `S = ((px − stageLeft)/s, (py − stageTop)/s, 0)`，射线 `E' + λ(S − E')`（CSS 坐标，`E' = (ox, oy, d)`）；倾斜平面法线 `n = (0, −sinθ, cosθ)` 过 `(0, H/2, 0)`；`λ = [n_y(H/2 − oy) + n_z(0 − d)] / [n_y(S_y − oy) + n_z(0 − d)]`；交点 `(wx, wy)` → `x = wx`，`y = H/2 + (wy − H/2)/cosθ`。用于把 presenter 给的 DOM 锚点变回平面坐标。

**(g) 反向到指定深度（新增 `screenToDepth`，手牌立板用）**：`.tda-hand-layer` 是 flat 层，其中卡牌都在世界 `Z = handAt.z`（`handLayerPlacement`，`layout.ts:151-154`：landscape `(1000−550)·sin28° + 40 ≈ 251.3`，portrait `(1340−750)·sin22° + 40 ≈ 261.0`）：`λ = (d − z0)/d`；`X = ox + λ(sx − ox)`，`Y = oy + λ(sy − oy)` → 世界 `(X, −Y, z0)`。空中层"手牌处爆发 / 光束端点"放这里，透视大小自然正确。

**(h) 锚点口径**：`PowerFxContext` 全是 `getBoundingClientRect` 中心（透视下盒中心 ≠ 元素中心精确投影，一般 ≤ 3 px；0×0 的 `.tda-coins-anchor` 是精确点）。P1 走路 A（client 像素 → `toPlane`）；P2 起加 `Anchors` 注册表（路 B）：`TableScene` 每次渲染推 `center / seats / cardPlacements` 的平面位姿（含 z：聚焦 +46 `CardLayer.tsx:74`、拖动 60 `layout.ts:223-226`），签名脚本直接取。隐私：只登记 `data-layer="table"` 的公开牌 id；fx3d 目录 grep 不得出现 `privateGame | omniscientGame | SeatView.hand | OmniscientView`。

### 1.3 画布与 DOM 的尺寸同步

- `ResizeObserver(.tda-table)` → `layout()`（`FxStage.ts:105`）：重算 metrics、两组相机、`setSize`（只在尺寸真变时）、`dirty = true`；枭熊 `popover.setWidth/Height` 只改 iframe 尺寸不重建。
- 方向切换（`fitPlane` 的 `width < 640 || width < height·0.9`）时平面尺寸与 tilt 都变：长寿效果（场地环、等待）持有**平面坐标**而非 three 坐标，每帧 `sync()` 时重新 `local()`（沙盒"spawn 不捕获尺寸、每帧从 settings 解析"的规则，README:306-322）。
- 地面画布：CSS `width/height = W/H px`（在 stage 缩放之内），后备存储 `W·s·g × H·s·g`（`g` 见 §2.3），宽度 clamp ≤ 2048（surface-gl 用 2560，`surface-gl.ts:148`；地面低频可更低）。极值：`.tda-shell min-height 480` 下桌面区可能接近 0 → `setSize(max(1, …))`，`hostW < 240 || hostH < 200` → off。

## 2. 渲染器策略

### 2.1 两个渲染器、分层脏标记、按需循环

- **默认：两个 `WebGLRenderer`**（空中直出 `.tda-fx3d-air`；地面直出 `.tda-fx3d-ground`），页内上下文 3 个。参数：`{ alpha: true, premultipliedAlpha: true, antialias: tier === "high", stencil: false, depth: true, powerPreference: high → "high-performance" / 其余 "low-power" }`，`setClearColor(0, 0)`，`scene.background = null`（沙盒 `Environment.js:55` 的实色背景去掉），`toneMapping = NoToneMapping`，`outputColorSpace = SRGBColorSpace`，`sortObjects = true`。地面渲染器 `preserveDrawingBuffer: true`（`surface-gl.ts:106` 同款做法）；空中 `false`。
- **后备（仅当实测上下文吃紧或 SwiftShader 丢上下文）**：单渲染器挂空中画布，地面场景渲进同一后备存储后 `groundCtx2d.drawImage(airCanvas, 0, ah − gh, gw, gh, 0, 0, gw, gh)`——WebGL viewport 原点在左下，`gh < ah` 几乎恒成立（`fitPlane`：`H·s ≤ R.h/(cosθ·1.34) ≈ 0.845·R.h`），源矩形**必须取底部**；`gw ≤ aw`、`gh ≤ ah` 由 `s ≤ R.w/W` 与上式保证，后备尺寸直接用空中尺寸。启用它要在 runbook 记偏离与实测数字。
- **按需循环**（保留 `FxStage.ts:108-117` 口径）：`add()` → `wake()`；`frame()` 倒序 `effects[].update(dt, now)`，返回 false 即移除并 `dispose()`；队列空即停 rAF、`last = 0`；`dt ≤ 0.05`（沙盒 `Time.js:9 maxDelta 1/20`）。新增：① **分层脏标记** `airDirty / groundDirty`，每个 effect 声明 `layer: "air" | "ground" | "both"`，没变的画布不 `render()`；地面上静态印记（焦痕 9 s、整轮局场地环）只在生长 / 淡出的几百毫秒重画，其余靠保留缓冲（**只在地面无任何动态对象时**成立，否则整场景重画；节省按此口径算，不高估）；② `visibilitychange → hidden` 取消 rAF、恢复 `last = 0`；`mount.ts suspend()` 同；③ 持续类（W/G/E）受**节拍门**：high 60 / medium 30 / low 15 fps，低档静态时每 2 s 心跳一帧；④ 每帧顺序照搬沙盒 `App.frame`：tick → 写 `frame.uTime/uDelta/uResolution` → effects.update → `particles.flush()`（`addUpdateRange`，r186 `BufferAttribute.js:181` 存在）→ 池 update → Impulse（未缩放 dt）→ render（空中 → 地面）→ 调试模式写 `__tdaFx3d.stats()`。
- **reduce**：不挂载 stage；`composeFx` 全部走 2D（2D 层自身 reduce-aware：`particles.ts:146 add()` 只 `sleep(duration)`）；`test:server-browser` 四上下文零 RAF。

### 2.2 透明合成与颜色（按 r186 源码口径）

- 浏览器按**预乘**合成画布：`C = canvas.rgb + (1 − canvas.a)·DOM`。three 在透明清色上的混合（`WebGLState.js:675/679`）：非预乘 `NormalBlending` = `(SRC_ALPHA, 1−SRC_ALPHA, ONE, 1−SRC_ALPHA)` → 画布得到 `rgb·a / a`，正确预乘；非预乘 `AdditiveBlending` = `(SRC_ALPHA, ONE, ONE, ONE)` → `rgb·a + dst / a + dst.a`，alpha 累加到 1 处 DOM 被亮色替代（"加法光"的期望，叠得多的地方确实会压掉 DOM——所以**加法只用于小面积亮核**，大面积光用 cover 型）。沙盒标 `premultipliedAlpha: true` 的材质（ToxicMist `:330`、Singularity `:235`、CosmicShock `:181`）输出已预乘色，three 自动用 `(ONE, 1−SRC_ALPHA)`。**规则：材质 `premultipliedAlpha` 必须与片元输出口径一致**，移植时逐个核对（沙盒 `ParticleSystem.js:628` 注明非预乘）。
- 两个混合工厂（`fx3d/core/blend.ts`）：`cover(mat)`（预乘 over：烟 / 尘 / 焦痕 / 酸池 / 色调，**唯一能把毛毡压暗**的手段）与 `glow(mat)`（光 / 环 / 符文 / 火星：片元输出预乘色且 `alpha = saturate(max(r,g,b))·coverage`，层内叠加用 `AdditiveBlending`；对 DOM 等价于 screen 混合——深色毛毡上与加法几乎无差、浅色区域不过曝）。mobile 稿的"`alpha` 恒 0 的超亮像素"（`additiveOverlay`）依赖 WebGL 未定义行为，**不作默认**；若 P5 想启用，用 Playwright 黑底截图实验证明（白底 `drawImage` 探针无判别力，删除）。
- 颜色空间：所有材质 `toneMapped: false`；`Color('#rrggbb')` 在 `ColorManagement` 下存线性值 → 着色器在线性空间做加法与 `gradient4` → 片元末尾 `linearToOutputTexel(vec4(c,1)).rgb`（`WebGLProgram.js:782` 为每个 ShaderMaterial 注入；预乘材质在乘 alpha **之前**转换）。满亮度处精确回到 `tokens.css` 家族色（`--ember #ff7a45 / --tide #6fb7e6 / --grove #8bc46a / --arcane #c79bff / --crown #ffd36b`）与 `particles.ts:16-22 FAMILY` 的 main/bright。
- 不用 bloom、不用 EffectComposer（P1–P4）：沙盒自己 `bloomStrength 0.03`，靠剪影与软顶 `color /= 1 + color·0.14` 控高光（README:558-567）；叠加层上 bloom 会把光晕糊到 DOM 铭牌上，撞 `docs/design/ANTI_AI_FEEL.md` §3 规则 5。深度：空中层无场景几何，统一 `depthWrite:false`，大多 `depthTest:false`，靠 `renderOrder` 梯度（5 指示器 / 6 普通印记 / 7 符文 / 8 加法印记 / 9 气柱 / 10 普通粒子 / 11 丝带 / 12 加法粒子 / 14 冲击壳 / 16 核心）；`uSceneDepth` 绑 1×1 白图（0xffffff = 无穷远），所有 `softFade` 恒 1，沙盒 shader 不改一行。

`dpr = min(cap, √(budget/(R.w·R.h)))`。\* 噪声像素 = Σ(draw 覆盖像素 × 每像素 snoise 次数)，是唯一硬性着色预算（60 fps 下 150 M ≈ 9 G snoise-ALU/帧，集成显卡约可承受一半时长的 60 fps，故 high 档目标 p95 ≤ 16 ms 只对能力特效期间要求，持续态按 30 fps 节拍门）；**禁止任何全屏噪声 pass**（2.4 MP × 10 snoise 一次就吃掉 low 的全部预算）。变体表（§5）每行带 `budget` 字段，构建期静态校验不超本档。

- 390×844 手机：coarse → **medium**（桌面区约 390×600 × 1.25² ≈ 0.76 MP，10 步体积与 1500 粒子都在预算内）；视觉保真不在手机上先降。
- **软件 GL（SwiftShader）**：stage 挂载为 low（相机、画布、`project()` 全活 → `test:fx3d` 的 `res.ground` 成立），但 **效果路由默认走 2D**（`data-fx="canvas2d"`，`data-fx3d-stage="mounted"`），只有 `?fx3d=1` 时才把 16 个方法路由到 three（`data-fx="three-low"`）——这样 `test:browser` 冒烟不编任何重着色器、30 s 等待不受影响，`test:fx3d` 则用 `fx3d=1` 真正走一遍 low 档像素断言。
- **自适应降档（`AdaptiveGovernor`）**：量 **rAF 间隔** EMA（render() 的 JS 时间量不到 GPU 瓶颈）：连续 10 帧 > 24 ms（桌面）/ 40 ms（手机）→ 降一档；降到 off → 销毁 three、`composeFx` 内部 `active=false` 切回 2D（不换引用，presenter 无感）；会话内只降不升。`data-fx` 五态 `three-high | three-medium | three-low | canvas2d | none`，`data-fx-tier` 同步，供测试读。
- **用户开关**：帮助面板（`.tda-help`）加三态"特效：三维 / 贴图 / 关"（名词短语，`ANTI_AI_FEEL` 文案规则），存 `localStorage["three-dragon-ante.fx"]`（与 `three-dragon-ante.sound.v2` 同模式，try/catch），缺省三维。
- RT：high 档 P5 可选后期链 = 场景 RT（RGBA8 同画布尺寸）+ 扭曲 RT（半分辩 `HalfFloatType`，沙盒 `PostProcessing.js:51-52`）+ 1 次合成 pass；P1–P4 与 medium/low 永远直接 `renderer.render`。
- **深度代理**（P5 可选，high/medium）：`cardPlacements()` 公共位姿当 140×247 代理 quad 用 `MeshDepthMaterial({depthPacking: RGBADepthPacking})`（沙盒 `PostProcessing.js:49` 同法）渲进半分辩深度 RT → 粒子 / 气柱对卡牌软相交；只在 settled 牌上开，与 CSS 过渡不同步就关。

### 2.5 后期（扭曲 / 调色）在透明叠加下怎么做

- **调色**：没有全局 grade（只会影响我们自己的像素，且沙盒 `GradeShader.js:99` 写死 `alpha = 1` 会让整层变黑）；颜色全部来自家族调色板 uniform。
- **闪光**：沙盒 `ScreenFlash` 不作全屏 pass；改为空中层一张只覆盖 `.tda-table` 的 quad，`alpha ≤ 0.08`、`≤ 120 ms`，用于结算 / 传说降临（不违反 ANTI_AI_FEEL 规则 5——该规则针对渐变 / text-shadow / box-shadow 光晕 / 毛玻璃；HUD 在 `.tda-table` 之外不受影响）。
- **震动**：沙盒 `CameraShake` 的 trauma 模型（`shake = trauma²`，三组不等频正弦）替换 `particles.ts:132` 的随机 translate，仍写 `.tda-table.style.transform`（两张画布 + DOM 一起动），幅度上限不变（≤ 5/4 px）。
- **扭曲（P5，high 档开关）**：(a) 自扭曲——`LAYER.DISTORTION` 层写偏移到半分辩 RT，`DistortionShader`（`:33 offset = (d.rg−0.5)·2·d.b·d.a·uScale`）对**我们自己的场景 RT** 重采样，只弯特效像素（星云 / 气柱自身被透镜弯、热浪里的火星被折射仍成立）；(b) **毛毡快照扭曲**——`surface-gl` 是同源画布且 `preserveDrawingBuffer: true`（`surface-gl.ts:106`），每次 layout 后 `new CanvasTexture(surfaceCanvas)` 一次（≤ 2560 宽，静态桌面），地面层在热浪 / 透镜足迹内按位移重采样该快照并以覆盖度作 alpha 写出 → 真正"弯曲毛毡纹理"；只弯静态桌面，牌与 HUD 不弯（它们是实物，视觉成立）；足迹用 `uShape` 裁到桌内；surface 退回 CSS（`dataset.fallback`）时无快照 → 跳过。

## 4. 脚本模型：相位机与 presenter 衔接

### 4.1 相位

```
Idle ─spawn→ Arm(前奏，与 SETTLE 重叠，≤300 ms，不等待)
        ─→ Cast(A) ─[有 choice]→ Hold(W，循环直到 release) ─→ Resolve(R × 目标/流向) ─→ Fade(≤250) ─→ Done
                    └────────────（无 choice：Cast 直接进 Resolve）────────────────┘
Sustain(G) / Environment(E)：独立长寿 FieldFx，键 = FieldLayer item.id（`${kind}:${seatId}:${sourceCardId}` / `archmage:${seatId}`，FieldLayer.tsx:33-34），随 game.effects 出现 / 消失（淡出 820 ms 与 FieldLayer.tsx:51 一致）
Dust(D) / Slap(H)：无相位的瞬时脚本
```

对应沙盒 `Ability.js` 的 `IDLE/TRAVEL/IMPACT/FADE/DONE`：Arm ≈ `onSpawn._muzzleFx`；Cast ≈ `TRAVEL`（起步缓动按时间不按进度）；Resolve ≈ `onImpact`；Hold ≈ IMPACT 相 `onFade(dt, t∈0..1)` 冻结 t 并用无周期包络（`AcidAbility.js:59 boilEnvelope` 三正弦）驱动；Fade ≈ `collapse`。池化契约："spawn 必须完全重置状态，destroy 必须释放，二者都不许分配"。

### 4.4 家族脚本接口与"词汇"

```ts
export interface ScriptCtx { stage: FxStage; kit: PrimKit; fx2d: FxLayer; cue: PowerCue; events: readonly PublicEvent[]; anchors: PowerFxContext & { reg: Anchors | null }; palette: Palette; tier: Tier; source: Anchor; targets: TargetAnchor[]; others: string[]; sound(kind: string, key: string): void; now(): number; gen: number; cancelled(): boolean }
export interface FamilyScript {
  arm?(c: ScriptCtx): Phase;                                   // ≤ 300，与 SETTLE 重叠
  presence?(c: ScriptCtx): Promise<void>;                     // 传说到场；默认 Mark + Collar + Volume（≤ 700 主体）
  cast(c: ScriptCtx): Promise<void>;                          // A（+ 内联 R）；非等待 ≤ 2000 且 ≤ 对应 2D case
  resolve?(c: ScriptCtx, t: ResolveTarget): Promise<void>;    // {to: "coins"|"hand"|"deck"|"discard"|"ante"|"flight"|"stakes"|"hole", seatId?, amount?, point}
  hold?(c: ScriptCtx, area: Rect | null, who: "self" | "other", kind: HoldKind): Handle;   // W
  sustain?(c: ScriptCtx, item: { kind: EffectKind | "archmage"; seatId: string }, area: Rect): Handle;  // G
  environment?(c: ScriptCtx, item: { kind: EffectKind }): Handle;                                   // E
}
```

- `hold/sustain/environment` 由 `composeFx.ambient()` 路由触发：`hold:` 到来时拿不到 cue → `script()` 处理 cue 时记 `lastCastFamily / lastChoiceKind`；FieldLayer 的 id `kind` 直接映射脚本。`HoldKind` 由 `Choice.code`（`types.ts:16`：`GIVE_DRAGON_OR_GOLD / BLUE_DESTINATION / NEXT_GOOD_DRAGON_POWER / KEEP_SEER_CARD / REPLACE_OTHER_FLIGHT_CARD / TRIGGER_REPLACEMENT …`）映射为 `demand | destination | order | pick | confirm`。
- 先知借用：`PowerCue.family = effectFamily`（`power-sequence.ts:41`）→ 先跑 `prophet.arm`（圣杯升起、紫火变为借用色，300 ms），再跑借用家族 `cast`；二者之和 ≤ 原 2D `beam + sigil`（≈ 1500）。
- 无目标回退：任何锚点为 null → `kit.flare(source, palette, form)`（按家族调色板与 GlyphForm 变形，不再退化成同一闪光）。
- 词汇（沙盒直取）：**A** `_muzzleFx`——源牌 Shell 小壳（squash .55）+ 26–30 motes + `Impulse.flash(0.08)` + Mark `grown 0→1`（outQuint）+ Volume `height` 升起（outCubic）+ Beam 前锋沿线每 N 单位撒 SCORCH 小印（`_creepFx`）；**W** ZoneIndicator 呼吸 + sweep 读头 + ticks 转动（Collar / Zone 上）、Cascade `_charge 0..1` 推 Wisps `uCharge` 与 Mark 亮度、Volume `boil` 冻在包络；**R** `onImpact`——目的地 SHOCKWAVE（life .75，width .055）+ SCORCH 长留（9 s）+ Shell 一次性 + 粒子喷涌 + `Impulse.shake(0.3–0.7)`，按目的地分：金币堆 RIPPLE 金环 + 火星；手牌 Shell AIR 小壳在 `handAt.z`；牌库 / 弃牌堆 Volume 短 puff + Ring；前注区 Ring sweep；牌阵 Fissure / Mark 剑痕；**G** `_auraFx` RateEmitter（bubbles 44/s、motes 110/s 量级按档缩）+ 无周期包络 + `Impulse.rumble(0.035)` 仅 high；**E** 地面长寿 Decal（藤蔓 = ARC 绿改色 + LEAF 落叶；霜 = FROST；灰 = DUSTRING 慢速）+ FieldTint quad。
